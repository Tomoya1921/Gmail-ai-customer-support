# AI Customer Support Assistant — Phase 2

問い合わせ専用Gmailアカウントの受信トレイから未処理メールを取得し、OpenAIで返信案を生成して元スレッドに下書きを保存する単発実行ツールです。最終確認・修正・送信は人間がGmailで行います。メールの送信・削除処理はありません。

## 処理対象と上限

- `INBOX` 内で「AI処理済み」が付いていないメールを対象にします。
- 「AI返信テスト」の手動付与は不要です。既読・未読は条件にしません。
- 送信済み・下書き・迷惑メール・ゴミ箱は除外します。
- 過去の未処理メールも対象です。問い合わせ内容の自動分類はしません。専用アカウントで使用してください。
- 1回の上限は **5件**。`src/config.ts` の `MAX_EMAILS_PER_RUN` が初期値です。
- 任意の環境変数 `MAX_EMAILS_PER_RUN` で正の整数に変更できます。空文字・0・負数・小数・不正値は、認証やAPI呼び出しの前にエラーになります。
- 失敗・スキップしたメールも上限に数え、代わりのメールを補充しません。返信生成は対象メールにつき最大1回で、OpenAI SDKの自動再試行は無効です。

## セットアップ

1. Google CloudでGmail APIを有効化し、OAuth同意画面とデスクトップアプリ用OAuthクライアントを設定します。
2. OAuthクライアント設定をローカルの `credentials.json` に配置します。
3. ローカルの `.env` に `OPENAI_API_KEY` と `OPENAI_MODEL` を設定します。上限を変える場合のみ `MAX_EMAILS_PER_RUN` を指定します。秘密情報はGitへ追加しないでください。
4. `npm install` で依存関係をインストールします。

初回の手動実行では認証用URLが表示されます。ブラウザで認証すると `token.json` が保存され、次回以降は保存済み認証を利用します。既存のGoogle OAuth認証方式を維持しています。認証URLは初回の対話認証に必要なため表示しますが、APIキー・アクセストークン・リフレッシュトークン・client secretはログに出しません。

## 検証と実行

```sh
npm run test
npm run typecheck
npm run build
```

テストは架空データとモックを使用します。実行入口を読み込まず、`.env`、`credentials.json`、`token.json`、`mail.txt` は読みません。Gmail/OpenAI APIも呼び出しません。

次のコマンドは**実際のAPIを呼び出して下書きとラベルを作成します**。

```sh
npm run dev
# またはビルド後に
npm start
```

PowerShellで、そのセッションの上限を変更する例：

```powershell
$env:MAX_EMAILS_PER_RUN = '3'
npm start
```

## 処理とエラー

上限分のIDをページネーションで収集し、順に取得・返信生成・下書き保存・処理済みラベル付与を行います。本文取得時にも対象ラベルを再確認します。「AI処理済み」がなければ自動作成します。

下書き作成に成功した後だけ元メールに「AI処理済み」を付けます。1件失敗しても次のメールへ進みます。失敗を含む実行は終了コード1、全件成功または対象なしは0です。認証・対象一覧取得など実行全体に必要な処理の失敗は、その実行を停止します。

ログはイベント名、失敗段階（`fetch` / `generate` / `draft` / `label`）、選択・成功・失敗・スキップ件数です。メールアドレス・件名・本文・メールID・生のAPI例外は出力しません。`startup_failed` は必須設定・認証・一覧取得などを確認してください。GmailとOpenAIの通常APIリクエストは60秒でタイムアウトし、自動再試行しません。

## 制約と定期実行への接続

- 永続的な処理記録はありません。下書き作成後にラベル付与が失敗した場合や、下書き作成の結果を通信障害で受け取れなかった場合、次回実行で重複下書きができる可能性があります。特に `draft` / `label` で失敗した場合は、再実行前にGmailの下書きを人間が確認してください。
- 同時実行による重複は防ぎません。複数プロセスを重ねて実行しないでください。
- Gmailの検索順で上限件数を選択します。失敗メールの繰り返しや大量の新着により、古いメールの処理が遅れる可能性があります。
- 本文は従来同様、プレーンテキスト優先・HTML変換対応で最大6000文字をAI入力とします。本文内の個人情報を自動匿名化する機能はありません。
- `processInbox` は1回で終了する処理として分離しています。将来は初回認証を済ませた環境で、スケジューラーから約5分間隔で `npm start` を呼び出せます。前の実行が終わるまで次の実行を開始しない設定が必要です。今回スケジューラーの登録は行いません。
